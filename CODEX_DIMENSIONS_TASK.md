# Задача Codex: применить размеры из прайса к актуальному /next/

Работать только с актуальной архитектурой ветки `codex-current`.

Обязательные входные файлы:
- `next/app-registry.js`
- `data/forma-home-dimensions-from-price.tsv`

В TSV сейчас полный набор: 384 строки моделей с найденными размерами из прайса. Поля:
- `modelId`
- `sourceIds`
- `dimensions`

## Что сделать

1. Полностью прочитать TSV.
2. Не изменять `catalog.json` ради этой задачи.
3. Не использовать старый `next/app.js` как основной runtime.
4. Интегрировать размеры в текущий `/next/`, который работает через `next/app-registry.js`.
5. Сопоставлять по `modelId` и указанным `sourceIds`.
6. Размеры из TSV использовать только как fallback там, где у конкретного Variant/sourceId нет более точных размерных данных в исходных характеристиках.
7. Если в TSV несколько размеров через `|`, сохранить все значения; не выбирать одно произвольно.
8. В modal выводить отдельный блок `Размеры` для активного Variant. При смене Variant блок должен обновляться вместе с ценой, фото и sourceId.
9. Не угадывать значения и не переносить размеры между похожими моделями.
10. Не менять цены, фото, цвета, группировку, registry/manualEvidence, root site и дизайн.
11. Не добавлять товары, которых нет на сайте.

## Проверка

Перед завершением обязательно сообщить:
- сколько строк прочитано из TSV (ожидается 384 модели);
- сколько моделей TSV найдено в текущем каталоге;
- сколько Variant получили fallback-размеры;
- сколько моделей получили fallback-размеры;
- какие строки TSV не применены и почему;
- lost sourceId = 0;
- duplicate sourceId = 0.

Запустить:
- `node --check next/app-registry.js` и всех других изменённых JS;
- существующий registry audit;
- `git diff --check`.

Если browser tooling доступен — проверить несколько modal с новыми размерами. Если недоступен — написать это явно.

Сделать отдельный commit. PR создавать только если среда позволяет.
