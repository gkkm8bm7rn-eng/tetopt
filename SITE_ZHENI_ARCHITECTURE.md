# САЙТ ЖЕНИ — архитектурный контракт

Эта ветка — единственная рабочая площадка для новой цельной версии FORMA HOME / ФОРМА ХОУМ.

## Цель

Сохранить покупательское поведение последней удачной версии сайта до серии performance/Safari-упрощений, но заменить многослойную реализацию простой и легко редактируемой архитектурой.

Эталон поведения до упрощений: commit `04d249a4225a6d452ada2a8c11083d15f5bfcb26`.

Актуальные данные, фотографии и более поздние подтвержденные решения берутся из текущего репозитория и ручных реестров, а не откатываются к старому состоянию.

## Неприкосновенный принцип

Один путь данных:

`raw source -> deterministic build/normalization -> catalog.json -> storefront`

Браузер ничего не группирует заново, не угадывает цвета из произвольного текста и не исправляет DOM поздними патчами.

## Финальный runtime

В публичной сборке должны остаться только действительно нужные файлы:

- `index.html` — структура страницы;
- `assets/site.css` — один основной CSS;
- `assets/site.js` — один storefront/runtime;
- `data/catalog.json` — единственный публичный каталог;
- `data/site-content.json` — тексты сайта;
- `data/commerce-config.json` — контакты, корзина, заказ, доставка/оплата;
- `data/search-config.json` — правила поиска;
- `data/merchandising.json` — порядок выдачи;
- `data/recommendations.json` — подтвержденные рекомендации;
- `data/legal-config.json` — подтвержденные юридические данные;
- `assets/products/{sourceId}/...` — только используемые подтвержденные фотографии;
- локальные шрифты и минимальные служебные файлы (`robots.txt`, `sitemap.xml`, favicon), если они реально используются.

Названия могут быть уточнены при миграции, но каждый тип данных имеет ровно один источник истины.

## Данные товара

`model` — одна конструктивно одинаковая карточка товара.

`variant` — одна реальная покупаемая строка с собственным `sourceId`, ценами, характеристиками и фотографиями.

`colorCard` — одна видимая покупателю кнопка исполнения. Клиентский код не создает и не разделяет `colorCard`.

Минимальная форма покупательского исполнения:

```json
{
  "favoriteId": "stable-id",
  "defaultSourceId": "123",
  "cartSourceId": "123",
  "sourceIds": ["123"],
  "colorLabel": "Бежевый / орех",
  "upholsteryColor": "Бежевый",
  "upholsteryHex": "#d8c7ad",
  "baseColor": "Орех",
  "baseHex": "#6f4d36"
}
```

Не все цветовые поля обязательны. Если подтвержденного цвета нет, в интерфейсе используется короткое исходное описание исполнения текстом. Никаких буквенных заглушек и придуманных цветов.

## Фотографии

Фотографии всегда задаются массивом `images` конкретного `variant`.

```json
{
  "sourceId": "123",
  "images": [
    "assets/products/123/01.webp",
    "assets/products/123/02.webp",
    "assets/products/123/03.webp"
  ]
}
```

Код одинаково работает с 1, 2, 3 и большим количеством фотографий. Первая фотография — подтвержденный общий вид. В листинге заранее не загружается вся галерея.

## Покупательский путь

Обязательные функции:

- каталог с коммерчески осмысленным порядком;
- поиск и фильтры;
- реальные исполнения одной модели без несуществующих комбинаций;
- атомарная смена фото, цен и характеристик при выборе исполнения;
- избранное без регистрации;
- отдельный экран/режим избранного;
- Share/copy-link для избранного;
- корзина с точным исполнением и количеством;
- Share/copy-link для корзины/заказа;
- недавно просмотренные;
- подтвержденные рекомендации;
- оформление заявки без регистрации;
- отправка одного и того же объекта заказа через WhatsApp, Telegram share, e-mail и копирование текста;
- адаптивность 360/390/768/1024/1440;
- ленивые изображения и легкая начальная загрузка.

## Что запрещено в финальной версии

- несколько параллельных storefront-файлов;
- отдельные JS-патчи для конкретных товаров;
- `MutationObserver`, который после рендера исправляет названия/цвета/варианты;
- повторная группировка в браузере;
- декартово произведение `обивка x основание`;
- автоматическое придумывание цветов;
- видимые `sourceId`, `арт.`, `мод. GH-*`, упаковочные хвосты;
- несколько независимых loader-ов каталога;
- старый service worker/кэш без доказанной необходимости;
- БД, авторизация, CMS или тяжелый framework без реальной необходимости.

## Миграция

1. Сохранить все актуальные данные, фотографии и ручные решения.
2. Зафиксировать эталонные покупательские сценарии старой удачной версии.
3. Сформировать один проверенный `data/catalog.json` с готовыми `model -> variant -> colorCard`.
4. Перенести покупательские функции в один `assets/site.js`.
5. Перенести оформление в один `assets/site.css`.
6. Проверить данные и сценарии автоматически.
7. Проверить реальным браузером desktop/tablet/mobile.
8. Только после подтверждения удалить старые runtime-модули и `/next/` из этой ветки.
9. `main` не менять до отдельного подтверждения владельца.

## Критерий успеха

Не количество переписанного кода, а результат: покупатель быстро открывает сайт даже на слабой сети, видит реальные товары и красивые понятные исполнения, легко выбирает точный вариант, сохраняет/делится подборкой и без препятствий отправляет точный заказ менеджеру.
